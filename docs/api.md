# 接口约定

应用默认地址为 `http://127.0.0.1:8000`，交互式文档为 `/docs`。字段名称保持英文以便程序接入，接口摘要和错误提示使用中文。

| 方法与路径 | 请求 | 返回 |
| --- | --- | --- |
| GET /health | 无 | 数据库连接、模型名称配置、重排序开关、上传上限 |
| GET /documents | 无 | 文档标识、名称、格式、哈希、状态、数量和时间；隐藏内部路径 |
| POST /documents/upload | multipart 字段 file | 导入结果与 duplicate 重复标记；处理完成后才返回 |
| GET /documents/{document_id}/file | 文档标识 | 原始文件；不存在或未完成则404 |
| POST /search | query、可选 top_k | 片段、来源和检索/重排序分数 |
| POST /chat | question | answer 字符串与 citations 引用列表 |

## 搜索和问答

```json
{"query":"北京住宿标准是多少？","top_k":5}
```

```json
{"question":"北京住宿标准是多少？"}
```

问题去首尾空白后长度为1—2000字符；top_k为1—50的 JSON 整数，不接受布尔值、字符串或小数，实际结果还受系统最终数量上限及可用候选限制。

错误响应统一使用 detail 字段，例如：

```json
{"detail":"问题不能为空。"}
```

主要状态码：413请求或文件过大；415格式不支持；422请求校验或文档解析失败；502上游业务服务失败；500未预期错误。参数校验不回传原始输入。

文档状态为 indexing（处理中）、ready（已完成）、failed（失败）。相同字节内容已成功导入时返回首次成功记录；同名不同内容不自动覆盖旧版本。

## 健康检查

status为ok表示 Qdrant 当前可连接且两个模型名称非空；不验证模型密钥、余额、推理效果或集合内容完整性。max_upload_mb用于页面展示与后端一致的文件上限，代码按 MiB 换算字节，页面简写 MB。

## 可选重排序

启用后向 RERANKER_BASE_URL 的完整地址提交：

```json
{"model":"已配置模型","query":"住宿标准","documents":["原文片段一","原文片段二"],"top_n":2}
```

响应要求：

```json
{"results":[{"index":1,"relevance_score":0.9},{"index":0,"relevance_score":0.6}]}
```

index从0起，对应输入片段；检查越界、重复、非有限分数和返回数量。已启用而调用失败时返回错误，不会静默忽略重排序。

## 文档原文与隐私

返回的引用位置由后端关联原片段。当前没有身份认证和按用户授权过滤，不应将接口直接作为多个客户共用的公网知识库。
