# 架构与边界

## 模块职责

| 模块 | 职责 |
| --- | --- |
| config.py / domain.py | 配置约束、文档与片段等数据模型 |
| api.py | 路由、请求校验、生命周期、错误响应 |
| services.py | 组织导入、检索与问答流程 |
| loaders.py / chunking.py | 格式解析、定位与结构优先切块 |
| embeddings.py / vectors.py | 编码协议适配与 Qdrant 操作 |
| storage.py | SQLite 元数据、状态与恢复 |
| retrieval.py / rerank.py | BM25、RRF 与可选重排序 |
| generation.py | 模型请求与引用编号映射 |
| utils.py | 内容哈希、业务异常、日志 |

## 来源与切块

PDF 使用 pdfminer.six 提取文字框，保留页码并将坐标转换为解析后页面的左上角坐标；Word 按正文段落、表格出现顺序记录章节和序号；Excel 按连续非空行及最多15行的批次保留工作表与区域范围。

普通长段落按字符窗口切分，默认800字符、重叠100字符。表格批次保持完整，因此可能超过目标长度。来源不跨块合并；长段落切片的 PDF 坐标仍是原始文本块范围，不声称精确到每个字符。

Excel 使用公式文本，不自动计算；不规则并排表格、跨批次表头及整表聚合仍需针对实际文档评估。

## 混合检索

BM25 使用中文分词，并将章节与已有表头信息纳入词项。向量检索对问题编码并限制为当前可用文档。两路候选按 RRF 累加 `1 / (60 + rank)`，每一路内同一片段只计一次贡献，跨路可以累加。

默认两路各20条，融合保留12条，最终最多5条。分数不是答案置信度。当前两路顺序执行，外部编码或数据库故障时返回错误，没有自动退化为仅关键词检索。

## 状态与一致性

原始文件按内容哈希命名。SQLite 保存文档、片段正文和导入状态，Qdrant 保存向量及片段信息。内存检索只加载已完成文档的片段。

导入顺序为登记处理中、写原文件、解析编码、替换向量、提交 SQLite 完成状态、重建 BM25。失败后标为失败，重传时清理该文档残留向量；重启把中断任务标为失败。

SQLite 与 Qdrant 不是跨库事务；向量写入成功后，元数据提交仍可能失败。共享进程锁与已完成状态过滤减少中间数据被检索的风险，但不提供分布式一致性或后台自动重试。

原文下载根据当前上传目录、内容哈希和文件类型重新定位，不依赖历史元数据中的绝对路径；搬迁时仍需带上原文件并正确配置上传目录。旧路径字段保留以兼容已有记录与解析流程。

## 生成与引用

按排名选取正文总计不超过18000字符的完整片段，赋予本次 C 编号后提交给模型。此预算不包含 JSON、问题等额外开销，也不是 token 数量预算。

模型回答没有编号、编号不存在或明确拒答时，返回无足够证据提示；合法编号由后端映射到原始片段。该机制不校验每个事实与证据的语义关系，不能保证零错误。

## 运行边界

单进程、单工作区、内存 BM25。导入与检索共享可重入锁，网络等待也可能占用该锁；增加 worker 会产生各自的内存索引与锁，不能直接获得一致的多进程能力。

默认本机访问。需要多人账号、文档权限、版本管理、后台任务或更大规模时，应先明确需求，再增加对应实现及容量测试。
